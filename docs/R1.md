# R1 — Football clock and added time

Completed locally, 27 October 2026. Publication remains Batch 10. This adds the timing foundation for R2 reports; it does not implement those full reports or R3 law actions.

## User-visible behavior

- Two explicitly identified halves, with correctly labelled half-time and full-time whistles.
- Seeded synthetic added time in each half, including zero, short and longer examples. The announced whole-minute minimum and actual whistle are separate; some seeds finish later than the announced minimum. These are authored reproducible schedules, not an empirically calibrated referee-time model.
- First-half `45+2:00` differs from second-half `47:00`. The replay, event list, commentary sources, comparison scopes, shot chart, reports and interval controls use one shared clock.
- Enter a whole minute, `66:30`, `45+2` or `90+4`. `H2 45:00` denotes second-half kickoff when first-half added time makes `45` ambiguous. Recent/previous/next intervals use elapsed playing time, and Since half-time starts at the actual second kickoff.
- Latest/replay-end recovery includes the exact displayed end, including added-time seconds. At full time the closing interval includes the final whistle. Changing shortcuts also invalidates an old explanation.
- A full-time takeaway requires the actual revealed full-time event inside the selected interval. Reaching nominal 90:00, or another event with the same timestamp as the final whistle, is insufficient.
- Half-time is shown as a replay event/status; there is no forced real-world waiting period.

## Contract and compatibility

New generated/exported matches use package version 2, replay schema 0.6 and simulator 0.4. Evidence packets use schema 15. `t` is a monotonic playing-timeline coordinate: first-half added time shifts the start of the second half; the wall-clock half-time break is omitted. Every v2 event has an explicit period. Display minutes are derived from the period start rather than `t / 60`.

Clock metadata describes two contiguous 2700-second regulation periods, their starts and actual ends. The resource bound is 900 added seconds per half; this is a prototype contract limit, not a claim that football laws impose a 15-minute added-time maximum. Extended halves require an `added_time` event at regulation end with a whole-minute `minimum_seconds` no greater than actual added time. Each period starts at its kickoff and ends at its whistle. Validation covers time/order/period consistency and delayed evidence through the actual end.

Legacy v1 packages remain accepted unchanged, including their original 0–5400 timeline, histories, reports and shot values. Import/export preserves their version instead of silently rewriting user data. New generator exports use v2. To migrate an external producer, add explicit clock metadata and period fields and shift all second-half core/availability/report timestamps consistently; do not merely increase the v1 final-time limit. The historical simulator remains available explicitly as `simulateLegacy` for frozen regression fixtures and old event digests; the product defaults to the new generator.

Only revealed period starts, announcements and whistles enter the evidence packet's clock metadata. Future actual whistle times and future announcements are excluded. Historical context remains filtered at entry time; shot values retain their own availability cutoff; corrected reports supersede only when available. Comparison/exposure/chance tools use the actual match extent instead of a fixed 5400-second ceiling.

## Verification

- **28/28 test files pass**, including the new clock matrix and HTTP integration. Saved final run: local verification; no fresh live model calls.
- 60 new deterministic generated packages validate, with old/new import parity checks. Historical fixture construction explicitly retains v1 inputs where tests author their own fixed event timelines.
- New authored cases cover goals in first/second-half added time, cards, early/late substitutions, comparisons extending beyond nominal 90, delayed role history, delayed shot values, corrections, zero/long added time, malformed periods and announcements, and same-timestamp pre-whistle events. No future interval, history, value or whistle is silently revealed.
- `npm run check:clock` verifies first-half versus second-half clock interpretation, half-time navigation, the 90:00 announcement, final added-time selection, local full-time commentary and v1/v2 upload behavior. [Browser record](r1-clock-browser-check.json), [added-time result](r1-added-time-result.png).
- Existing usability browser regression passes with local fallback and controlled failures. It makes no model calls; R1 regressions can use `TOUCHLINE_CHECK_PREFIX=r1-usability` to keep historical Batch 9 captures intact.
- Relevant browser/test requests now select replay indices by time rather than depending on an old event number.

## Limits

No extra time, shootouts, abandoned matches, wall-clock live-feed synchronization or tracking is added. Ordinary reports retain inclusive endpoints, so adjacent reports may share a boundary event; matched comparisons remain half-open. Period metadata disambiguates equal-timestamp boundary records. The deterministic scenario evaluation is not a new model-quality benchmark. The new clock/generator changes the source distribution; comparative quality is rechecked in R5.
