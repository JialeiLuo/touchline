# R2 — Optional full prose reports

Completed locally, 27 October 2026. Publication remains Batch 10. R3's Explain this decision action is not included here.

## What changed

The existing short commentary is unchanged. An optional **Read a full report** disclosure adds a connected prose account with overview, first/second-half passages, shooting balance, relevant context, available incident accounts and a scope-appropriate conclusion. It is not a printout of every pass or a padded chronological event list.

Three scopes are supported:

| Choice | Bounds | Meaning |
|---|---|---|
| Selected spell | The currently selected revealed From/To interval | A report on the missed spell, including its opening/closing score; explicitly not a whole-match report |
| Match so far | Kickoff to the selected replay event | A developing account, marked provisional until the actual full-time event is revealed |
| Full-time report | Kickoff through the revealed full-time event | The complete recorded match, including added time; unavailable at nominal 90:00 or a pre-whistle event sharing the whistle timestamp |

Core chronology covers both teams regardless of focus. Team/player choices can prioritize supporting context. Quick/Tactical and investigation/ranking choices continue to control the short commentary; they do not silently truncate or change the full report. No report is generated automatically by playback, opening the disclosure or changing preferences.

An ordinary generated match produces several connected paragraphs, often a few hundred words. Quiet records stay shorter. Decisive events are expressed through their score context (ahead, level, extending a lead, reducing a deficit) rather than copied goal labels. Added-time announcements and the actual whistles remain distinct. Condensed dense passages retain all goal/dismissal source references and explicitly disclose the condensation; opening and closing major incidents remain in the prose.

## Hands-on instructions

1. Refresh http://127.0.0.1:8769/ on this computer.
2. Select **Try the substitution example**. Read short commentary first if desired.
3. Open **Read a full report** below the commentary workspace.
4. Keep **Selected spell** to read 55–66, or choose **Match so far** to include the earlier match.
5. Select **Write report**. Playback pauses while the request is prepared.
6. Read the normal paragraphs. Open **Sources for this paragraph** only when you want the supporting records; those disclosures include scope/history/report references where relevant.
7. Use **Download report text** for a plain-text copy. The glossary still works on highlighted terms in the displayed report.
8. Move the replay slider to its end. **Full-time report** becomes available only after the actual whistle. Select it and write the report to include the full match and added-time finish.

If replay/focus/report scope changes, the earlier report is marked stale and its download disabled. A response arriving after a change is suppressed. Select Write report to update deliberately. Expired server-held packages block new reports with a reload instruction. A connection failure leaves an explicit retry message; the simple event recap remains available through the existing controls.

## Evidence and wording

`server/reports.cjs` normalizes the scope before using the same validated packet, football tools, supplied histories and story candidates as short commentary. Source-owned prose describes recorded chronology, calculated scores/attempts and supported context. A small optional model selection can choose supporting context IDs; the model does not write unrestricted report prose. The UI labels online context selection separately from the local evidence-based report.

Reported/corrected incident descriptions are attributed accounts, not established official decisions. Only available corrections supersede older reports. Missing role history does not become no experience. Before/after comparisons do not establish causation. Off-ball pressure, intent, emotions, injuries and manager effectiveness are not invented to imitate a journalist's voice. A final result never appears in an earlier scope just because the source package contains the complete match.

The chronology is neutral and mandatory; the model cannot drop a late goal or dismissal by selecting other context. Sources are collapsed under each paragraph, with event clocks, available account text, earlier history references and stated comparison windows. Underlying source lists display the first 30 events when large; the full validated input remains downloadable from match settings. Context outside the selected spell retains its labelled source scope.

## Bounds and recovery

| Control | Limit |
|---|---:|
| Model requests per report | At most 1; no automatic retry |
| Online selection deadline | 12 seconds |
| Model output | 800 tokens (context IDs, not prose) |
| Encoded request | 24,000 bytes |
| Accepted/streamed response | 64,000 bytes |
| Conservative token reservation estimate | 26,000 |
| Optional context paragraphs | At most 3 |
| Prose target | 1,200 words |
| Browser request timeout | 20 seconds |

The token reservation uses encoded request bytes plus framing/output allowances and is deliberately conservative, not exact tokenization or a billing guarantee. Reported token usage is retained separately; unknown usage is null. Unusually long supplied names/shape labels can exceed the prose target and produce an explicit length-exception field. Large incident collections are summarized with full accounts retained in source disclosures rather than copied into an unbounded report.

Each actual online attempt reserves one existing persistent demo allowance unit. Report requests share the online concurrency lock with short commentary. If another online request is active, a local report is delivered without another model call. Successful online reports use a scope-specific cache; cache hits make no new model request. Local fallbacks are not cached as online successes.

Unconfigured inference, unavailable allowances, rejected/duplicate/unknown context IDs, incomplete output, excessive response size, network/provider failure or cancellation retain a labelled local report. Uploaded descriptions/names are treated as data; the model receives only a bounded candidate catalogue and cannot request tools or external actions on this route.

The optional selector follows [official structured-output guidance](https://developers.openai.com/api/docs/guides/structured-outputs). Schema constraints help control output shape; they are not proof of factual correctness. The application separately validates selected IDs and owns the report text.

## Remaining limits

The writing is controlled and can sound formulaic. It is a connected source-grounded report, not unconstrained human-level sports journalism. No independent fan or football-expert study is claimed. Context choice and readable interpretation still need the broader R5 comparison/review. The report route is a one-pass selector, not a second agent investigation. Full translation, voice and law explanations remain outside R2.
